eggd_cgp-qc-flags — how the app works

A DNAnexus app that reads PURPLE's purity summary and turns it into a structured QC report with named confidence flags. Unlike the other apps in this series, most of its logic is a Python script embedded directly inside the bash file via a heredoc.

Author Joo Wook Ahn Date 5 July 2026

01 What this app does

PURPLE's purity TSV is machine-readable but not immediately actionable — a scientist reviewing a sample still has to know which purity/ploidy/confidence-interval combinations indicate an unreliable fit. This app encodes that domain knowledge as six named flags (PURITY_FLOOR, WGD_SUSPECT, FLAT_GENOME, WIDE_CI, NO_TUMOR_BESTFIT, LOW_SNV_COUNT), computed from simple numeric thresholds against PURPLE's own output, and writes them into a fixed 16-column TSV that a downstream IGV-report app displays alongside the copy-number data.

02 The flag logic

FlagTriggerMeaning
PURITY_FLOORpurity < 0.20Near the noise floor of the backbone panel — fit may be unreliable

FLAT_GENOMEdiploid proportion > 0.85Weak copy-number signal; the purity anchor itself is less certain

Always PASS or a flag list, never a hard failure — mostly

If no thresholds are crossed, the report's flags column reads PASS. The one exception is the NO_TUMOR best-fit recovery, which can abort the whole app — see §04.

04 Key concept: a Python heredoc inside a bash app

This app is the only one in the workflow whose core logic is written in Python rather than shell arithmetic. Rather than writing a separate .py file and bundling it (the pattern used by eggd_cgp-purple and eggd_cnv_chr_strip for their reusable helper modules), this script embeds the Python source directly using a heredoc — because the logic here is used exactly once, in exactly one place, with no need for unit tests or reuse from another app.

python3 - "${sample_id}" purity.tsv purity_range.tsv sigs.tsv cuppa.tsv << 'PYEOF'
import sys, csv
sample_id = sys.argv[1]
# … the rest of the Python program …
PYEOF

python3 - tells Python to read its program from stdin rather than a file; the heredoc (<< 'PYEOF' … PYEOF) supplies that stdin. The five positional arguments after python3 - become sys.argv[1:] inside the Python program — this is how bash variables (sample_id, and the local filenames from the earlier dx download calls) cross into the embedded script, without any environment-variable trick.

Why quoted 'PYEOF' and not PYEOF

Quoting the heredoc delimiter disables bash's variable/command substitution inside the body — essential here, because the Python source itself contains many $-free but curly-brace-heavy syntax (f-strings like f"{purity:.3f}") that bash would otherwise try to interpret as its own parameter-expansion syntax.

05 Function walkthrough

Bash setup: guard, download, optional-input brancheslines 12–27SETUP

The usual sample_id guard, then two required downloads. For the two optional inputs, an explicit if/else either downloads the supplied file or creates an empty stub with touch — deliberately not written as the shorter [[ -n "$x" ]] && dx download … || touch stub idiom, because that shorthand would silently fall through to touch even if the dx download itself failed (a subtle bug where &&/|| chains can mask a failure in the first branch).

Python: read purity TSV, compute the four numeric flagslines 43–72FLAGS 1–4

Standard csv.DictReader parsing of one data row, then four independent if checks appending to a flags list — each threshold documented in the header comment at the top of the file and reproduced in the table in §02.

Python: NO_TUMOR best-fit recoverylines 79–93FLAG 5

Covered line-by-line in §06 below — the one place in this app where a parsing failure is treated as fatal rather than logged and skipped.

Python: SIGS/CUPpa (best-effort) & write the reportlines 95–155FLAG 6 / OUTPUT

The SIGS and CUPpa sections are wrapped in bare try/except: blocks that swallow any error and fall back to 'N/A' — appropriate here because these two inputs are optional and out of scope for this workflow version (their stub files are empty), so a parse failure on an intentionally-empty file is expected, not a bug to surface. The final section writes the fixed 16-column TSV, with column order matching what the downstream plotter app expects by name.

06 Line-by-line: NO_TUMOR best-fit recovery

code.sh (embedded Python) : 82–93 The one place this app fails loudly rather than degrading gracefully 
if status == 'NO_TUMOR':
    flags.append('NO_TUMOR_BESTFIT')                                    # ①
    # For NO_TUMOR the range TSV is required to recover a best fit; a parse/empty
    # failure must abort rather than emit a 'successful' report with blank columns.
    try:
        with open(range_file) as f:
            rdr = csv.DictReader(f, delimiter='\t')
            best_row = min(rdr, key=lambda r: float(r.get('score', '9999')))  # ②
            bestfit_purity = float(best_row['purity'])
            bestfit_ploidy = float(best_row['ploidy'])
            info['bestfit_purity'] = f"{bestfit_purity:.3f}"
            info['bestfit_ploidy'] = f"{bestfit_ploidy:.3f}"
            info['bestfit_score']  = best_row.get('score', 'N/A')
    except Exception as e:
        print(f"ERROR: NO_TUMOR best-fit recovery failed from {range_file}: {e}", file=sys.stderr)  # ③
        sys.exit(1)                                                     # ④
①
The flag is appended unconditionally once status is NO_TUMOR. Unlike the four numeric flags in §05, this one doesn't depend on a threshold — the status itself is the trigger. Whether the report ends up complete or the app aborts is decided by what follows, not by whether the flag gets added.
②
min() with a key function, not a sort. min(rdr, key=lambda r: float(r.get('score', '9999'))) finds the single row with the lowest score value across the whole range TSV — PURPLE's own fit-quality metric, lower is better — without materialising a sorted list. The default '9999' inside .get() means a row missing the score column entirely is effectively deprioritised rather than raising immediately, though such a row would still need valid purity/ploidy columns to be selected as best_row without failing on the next two lines.
③
Explicit stderr write before exiting, distinct from the SIGS/CUPpa sections. Compare this to the bare except: info['total_snvs'] = 'N/A' pattern used for SIGS a few lines later — there, silently degrading is fine because that input is optional and out of scope. Here, a NO_TUMOR sample with an unparseable range file is a data-integrity problem in the workflow's core inputs, not an absent optional feature, so the failure is surfaced with a specific, actionable message identifying which file and which underlying exception caused it.
④
sys.exit(1) — the only fatal exit inside the embedded Python. This propagates as the python3 process's exit code; because the bash script has set -euo pipefail in effect, a non-zero exit from this heredoc immediately stops code.sh itself. The alternative this code deliberately avoids — catching the exception and writing blank bestfit_purity/bestfit_ploidy columns — would let the app report success on a qc_report.tsv that silently omits the one piece of information a NO_TUMOR row exists to provide.
