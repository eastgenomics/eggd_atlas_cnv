eggd_cgp-sage — how the app works

A DNAnexus bash app that runs SAGE, a somatic SNV/indel caller, in panel mode over a backbone gene panel. Its VCF output anchors PURPLE's purity fit. The longest-running stage in the workflow (~23 minutes on the reference test sample), it's also the app with the most reference-preparation work up front.

Author Joo Wook Ahn Date 5 July 2026

01 What this app does

src/code.sh wraps SAGE (Hartwig Medical Foundation's somatic variant caller), configured here in panel mode: it only calls variants inside a supplied panel BED (the backbone gene set), using a somatic panel-of-normals to filter out recurrent artefacts and a hotspot VCF to boost sensitivity at known cancer mutation sites. Its output VCF, when supplied to PURPLE, lets PURPLE anchor its purity estimate against actual somatic variant allele fractions rather than B-allele-frequency/depth-ratio signal alone — this is why PURPLE's script logs "Somatic VCF provided — will anchor purity" when it receives this app's output.

04 Key concept: htsjdk's FASTA requirements

SAGE is written on top of htsjdk (the Java toolkit most Java-based genomics tools — including GATK — are built on). htsjdk cannot read a bgzip-compressed FASTA directly the way samtools-based C tools can, and it additionally requires a sequence dictionary file (.dict) describing each contig's name and length, which some tools generate lazily but htsjdk expects to already exist alongside the FASTA.

# SAGE (htsjdk) cannot handle bgzf-compressed FASTA — decompress to plain .fa
bgzip -d -c ref.fa.gz > ref.fa
samtools faidx ref.fa
samtools dict ref.fa > ref.dict   # htsjdk requires .dict for sequenceDictionary
Cost of this step

The reference genome is roughly 3 GB compressed; the comment in the source (# Decompressing reference FASTA (~3 GB, ~1 min)…) exists specifically to set expectations in the job log for anyone watching a run in progress — this single decompression step is a meaningful fraction of the app's total runtime.

05 Key concept: dynamic memory sizing

Rather than hard-coding a Java heap size, the script queries the instance's actual total memory at runtime and reserves a margin for the OS and other processes:

MEM_GB=$(( $(free -g | awk '/^Mem:/{print $2}') - 4 ))
java -Xmx${MEM_GB}G -jar sage.jar …

free -g reports memory in whole gigabytes; awk '/^Mem:/{print $2}' picks out just the total-memory column from the line starting with Mem:. Subtracting 4 leaves headroom for the JVM's own overhead and any other processes on the worker, rather than requesting the JVM heap up to the machine's full physical memory (which would risk an out-of-memory kill).

Why not a fixed -Xmx value?

This app's dxapp.json declares an instance type, but instance types can be resized (e.g. to run on a bigger worker for a larger panel) without touching this script — the memory calculation adapts automatically rather than needing a matching manual edit every time the instance type changes.

Covered in §04 above, plus locating the Ensembl gene-data directory inside its tarball using find … -printf "%h\n" -quit — the -quit flag stops find after the first match, avoiding a pipe to head (and the SIGPIPE risk that pattern can carry under pipefail, discussed for the equivalent line in eggd_cgp-purple's walkthrough).

The flags -panel_only -high_depth_mode -skip_msi_jitter -skip_bqr -ref_sample_count 0 collectively configure "somatic calling restricted to the panel regions, tumour-only, without the microsatellite-instability and base-quality-recalibration steps that need a larger cohort or a matched normal to calibrate against" — all frozen from the original applet.

Checks the VCF exists, falls back to running tabix manually if SAGE didn't auto-generate the .tbi index, counts PASS-filtered variants for the job log, then uploads both files.

07 Line-by-line: memory calc & the tbi fallback

code.sh : 47–48, 74–76 Two small but easy-to-misread lines 
THREADS=$(nproc)                                                     # ①
MEM_GB=$(( $(free -g | awk '/^Mem:/{print $2}') - 4 ))                     # ②
…
# SAGE 5.x should auto-index; fallback if not
[[ -f "sage_out/${sample_id}.sage.somatic.vcf.gz.tbi" ]] \
    || tabix -p vcf "sage_out/${sample_id}.sage.somatic.vcf.gz"                # ③
①
nproc, not a hard-coded thread count. Same rationale as AMBER's -threads "$(nproc)" — automatically matches whatever CPU count the instance type provides.
②
Nested command + arithmetic substitution. The inner $(free -g | awk '/^Mem:/{print $2}') runs first and yields a plain number (e.g. 16); the outer $(( … - 4 )) is bash arithmetic expansion, which then computes 16 - 4 = 12. Two different kinds of $(...)/$((...)) syntax doing two different jobs in one line — command substitution feeding into arithmetic substitution.
③
A conditional fallback using bash's short-circuit OR. A || B runs B only if A fails (here, "the index file does not exist"). This is a defensive line, not a normal code path — the comment states the expectation ("SAGE 5.x should auto-index") while the code still handles the case where that expectation isn't met, rather than assuming it and letting a missing index propagate as a confusing failure much later in the workflow (the plotter app needs a tabix index to display the VCF track).
