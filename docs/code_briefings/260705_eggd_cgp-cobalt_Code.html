eggd_cgp-cobalt — how the app works

A DNAnexus bash app that runs COBALT to measure read-depth ratios across target regions — the second of PURPLE's three inputs. Structurally almost identical to eggd_cgp-amber, with one genuinely unusual line worth understanding.

Author Joo Wook Ahn Date 5 July 2026

01 What this app does

src/code.sh wraps COBALT (Hartwig Medical Foundation), which measures read depth in windows across the target regions and normalises it against a reference set to produce a per-window log-ratio — a signal of copy-number gain or loss independent of AMBER's B-allele-frequency signal. PURPLE combines both.

Like AMBER, this is a direct conversion of a pre-existing applet: COBALT's flags and the cobalt_tar output name are frozen unchanged.

04 Key concept: the .fai-next-to-.gz quirk

COBALT expects a bgzipped reference FASTA whose index file sits alongside it with a specific naming convention — ref.fa.gz.fai, not ref.fa.fai. DNAnexus downloads each input to whatever local filename the script requests, and the index file is downloaded under a plain name. Rather than re-running samtools faidx to regenerate an index at the name COBALT expects (slow, and redundant — the correct index already exists, just under the wrong name), the script creates a symlink.

dx download "${ref_fasta}" -o ref.fa.gz
dx download "${ref_fai}"   -o ref.fa.fai
# COBALT needs the .fai next to the gz, under a name matching <fasta>.gz.fai:
ln -sf ref.fa.fai ref.fa.gz.fai
Why -sf and not a plain copy

ln -sf creates a symbolic link (a pointer, not a duplicate of the file's contents) and the -f forces overwrite if the target name is somehow already taken. A symlink is essentially free — no data is copied — versus cp, which would duplicate a file that can be tens of megabytes for no benefit.

06 Line-by-line: the symlink trick

code.sh : 25–29 Make COBALT find the FASTA index under the name it expects 
dx download "${ref_fasta}"       -o ref.fa.gz          # ①
dx download "${ref_fai}"         -o ref.fa.fai         # ②
# COBALT needs the .fai next to the gz
ln -sf ref.fa.fai ref.fa.gz.fai                              # ③
①
The reference is downloaded under a plain name. -o ref.fa.gz is an arbitrary local filename choice — it doesn't have to match anything the source file was originally called on DNAnexus.
②
Its index, likewise, under a plain name. Both files are unrelated to each other by filename at this point — ref.fa.fai is just a name the script chose.
③
The symlink bridges the naming gap. Many bioinformatics tools that consume a bgzipped FASTA expect its index to be discoverable by appending .fai to the FASTA's own filename — i.e. ref.fa.gz.fai, not ref.fa.fai. ln -sf ref.fa.fai ref.fa.gz.fai creates a new directory entry named ref.fa.gz.fai that simply points at the already-downloaded ref.fa.fai — COBALT opens ref.fa.gz.fai and, via the symlink, actually reads the same bytes as ref.fa.fai, with zero extra disk usage or copy time.
