eggd_cnv_chr_strip — how the app works

The final stage of the workflow: writes Ensembl-named (1, 2, …, X, Y, MT) copies of the CNV call files for downstream apps, without touching the chr-prefixed originals. New code (not converted from a legacy applet), with a bundled pure-Python helper.

Author Joo Wook Ahn Date 5 July 2026

01 What this app does

Every other app in this workflow produces chromosome names in UCSC/chr-prefixed style (chr1, chrX, chrM) because that's what the reference genome and the IGV report expect. But some downstream consumers of the CNV call files — outside this workflow — expect Ensembl-style names (1, X, MT). Rather than making every upstream tool aware of two naming conventions, this app runs last and produces a second, Ensembl-named copy of each CNV file, leaving the chr-prefixed originals completely untouched.

Up to six files can be supplied — four from CNVkit, two from PURPLE — and each is optional; the app simply skips any that weren't provided.

04 Key concept: line-preserving rewrite vs. a CSV round-trip

The obvious way to "change one column of a TSV" in Python is to parse every row into a list of fields with csv.reader, modify the field, and write it back with csv.writer. This app deliberately does not do that. Instead, chr_strip.py reads the file as raw lines, splits each line on tabs by hand, replaces only the one field at the known column index, and rejoins with tabs — while explicitly preserving each line's original terminator character.

# the round-trip approach this app avoids:
import csv
rows = list(csv.reader(open("in.tsv"), delimiter="\t"))
# ... modify rows[i][idx] ...
csv.writer(open("out.tsv", "w"), delimiter="\t").writerows(rows)
# risk: csv.writer may re-quote fields, normalise line endings, or otherwise
# produce output that is not byte-identical to the input except for one column
Why the extra care matters here

These files are consumed by downstream tools with their own strict parsers. A CSV round-trip risks subtly changing quoting, whitespace, or line-ending conventions in columns that were never meant to change — gene names, coordinates, scores. The line-preserving approach guarantees the output is byte-identical to the input except for the chromosome column's text, which is the only documented promise this app makes.

05 Function walkthrough

Bash: dx-download-all-inputs, guard, strip() closurecode.sh : 10–28SETUP

dx-download-all-inputs --parallel is a DNAnexus SDK helper that downloads every supplied input file at once, in parallel, to a predictable path (~/in/<field_name>/<original_filename>) — a shortcut this app uses instead of six individual dx download calls, since the field names and expected filenames aren't fixed the way they are in, say, eggd_cgp-amber.

The local strip() bash function (taking three positional args — input field name, output filename, output field name) is called six times, once per possible input, and internally handles the case where that particular input wasn't supplied by checking whether ls ~/in/"$1"/* found anything.

Bash: strip() bodycode.sh : 21–28PER-INPUT

For a supplied input: calls the bundled chr_strip.strip_file() via a one-line python3 -c invocation, verifies the output file is non-empty (a successful call that produced zero bytes would indicate something went wrong even without raising), then uploads and registers it — the same upload pattern used throughout this workflow's apps.

06 The two Python functions

strip_chrom(chrom) -> strchr_strip.py : 8–13TRANSFORM

Purpose: convert one chromosome-name string from chr-prefixed to Ensembl style.

Key logic: if the value doesn't start with chr, it's returned unchanged — the function is idempotent: running it twice gives the same result as running it once, which matters because it means accidentally applying the strip to an already-Ensembl file is harmless rather than corrupting. Otherwise, the three-character chr prefix is dropped, and the special case chrM/chrMT → MT (not M) is handled explicitly, matching the Ensembl mitochondrial contig name.

strip_file(in_path, out_path, chrom_column=None) -> intchr_strip.py : 25–43TRANSFORM

Purpose: the line-preserving rewrite discussed in §04, applied to a whole file. Returns the number of data rows actually rewritten (useful for the job log, though this app doesn't currently print it).

See §07 for a full line-by-line breakdown — this is the one function in the app dense enough to deserve it.

07 Line-by-line: strip_file()

chr_strip.py : 25–43 Rewrite only the chromosome column, byte-identical otherwise 
def strip_file(in_path, out_path, chrom_column=None) -> int:
    with open(in_path, "r", newline="") as fh:                        # ①
        lines = fh.read().splitlines(keepends=True)                # ②
    if not lines:
        with open(out_path, "w", newline="") as fh:
            fh.write("")
        return 0
    idx = _chrom_index(lines[0].rstrip("\r\n").split("\t"), chrom_column)  # ③
    if idx is None:
        raise ChrColumnError(f"no chromosome column in {in_path}: {lines[0]!r}")
    out, n = [lines[0]], 0                                     # ④
    for line in lines[1:]:
        body = line.rstrip("\r\n")
        term = line[len(body):]                                # ⑤
        fields = body.split("\t")
        if len(fields) > idx and fields[idx]:
            fields[idx] = strip_chrom(fields[idx])              # ⑥
            n += 1
        out.append("\t".join(fields) + term)
    with open(out_path, "w", newline="") as fh:
        fh.write("".join(out))
    return n
①
newline="" disables universal-newline translation. By default, Python's text-mode file I/O silently converts \r\n and \r line endings to \n on read, and writes \n as the platform's native line ending on write — exactly the kind of "helpful" behaviour that would break the byte-for-byte guarantee this function exists to provide. newline="" turns that translation off on both the read and write sides.
②
splitlines(keepends=True). Unlike a plain .split("\n"), this splits on any of \n/\r\n/\r and keeps the terminator attached to each resulting string — so lines[i] already carries whatever line ending that specific line originally had, which the rest of the function relies on to reproduce it exactly.
③
Locate the column once, from the header. _chrom_index (not shown here — a short helper) looks for a caller-specified column name, falling back to a list of common header spellings (chromosome, chrom, #chrom, contig). This runs exactly once per file, not per row — the column position is fixed for the whole file.
④
The header line is appended to the output list completely unmodified. out = [lines[0]] — no split, no rejoin, no possibility of subtly altering it. Only data rows (from lines[1:] onward) go through the split/modify/rejoin logic below.
⑤
Splitting a line into its content and its terminator. body = line.rstrip("\r\n") strips whatever line ending is present; term = line[len(body):] then recovers exactly that ending as its own string (could be "\n", "\r\n", "\r", or empty for a file's final line with no trailing newline at all). This pair of lines is what lets the function reattach the original terminator later, rather than assuming one.
⑥
The only line that actually changes data. fields[idx] = strip_chrom(fields[idx]) replaces just the one field at the known chromosome-column index; the guard len(fields) > idx and fields[idx] skips a short/malformed row or an empty chromosome value rather than raising, and such a row is rejoined with its other fields untouched and does not count toward n (the returned "rows rewritten" count).
