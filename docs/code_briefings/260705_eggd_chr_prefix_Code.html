eggd_chr_prefix — how the app works

Stage 0 of the workflow: adds (or removes) the "chr" prefix on a BAM's chromosome names. This app pre-dates the eggd_atlas_cnv workflow and already had an array-based interface in production; v1.1.0 adds a second, single-file interface specifically so it can plug into this workflow, without changing the original array-based behaviour at all.

Author Joo Wook Ahn Date 5 July 2026

01 What this app does

Different reference genome builds and different tools disagree on chromosome naming: some call the first chromosome 1 (Ensembl convention), others call it chr1 (UCSC convention). A BAM aligned against one convention has that convention baked into its header, and every downstream tool needs to agree with it or fail outright. This app reheaders a BAM's chromosome names from one convention to the other using samtools reheader, without touching the read data itself — a header-only edit is essentially free compared to re-aligning.

The single-file branch is a self-contained if block near the top of main() that returns before reaching any of the original array-mode code. A job that supplies input_file_array and never sets input_bam executes exactly the same code path it always did — this is why the addition could go in as a minor version bump (1.0.0 → 1.1.0) rather than a breaking change.

04 Key concept: passthrough vs. skip

Both interfaces detect "this BAM is already in the target format" the same way — transform the header text with sed, then cmp -s the transformed text against the original; if they're identical, no reheadering is needed. What each interface does with that discovery differs, and the difference exists for a concrete reason.

# shared detection logic, used by both interfaces:
samtools view -H "$bam" > orig.sam
sed "$sed_cmd" orig.sam > new.sam
if cmp -s orig.sam new.sam; then
    # ... already in target format ...
fi

Array mode (v1.0.0, unchanged): if a file is already correctly formatted, the app logs a notice and moves on to the next file in the batch — that file contributes nothing to output_files/output_indices. This is fine in a general-purpose batch job: the caller can tell from the output array's length which inputs needed no change.

Single-file mode (v1.1.0, new): the same situation must instead copy the input through unchanged and still emit output_bam/output_bai. A DNAnexus workflow stage cannot conditionally skip its own outputs — the next stage in eggd_atlas_cnv (AMBER/COBALT/SAGE, all consuming this app's output_bam) needs a BAM link to exist regardless of whether reheadering actually happened.

Why this matters enough to be the whole point of v1.1.0

If single-file mode reused the array mode's skip behaviour, any sample whose BAM happened to already be chr-prefixed would produce a job with no output_bam at all — and the workflow's downstream stages, wired to that output, would simply never run. This one behavioural difference is why a new mode was needed rather than just adding single-file inputs to the existing code path.

05 Function walkthrough: single-file mode (new in v1.1.0)

if [ -n "${input_bam:-}" ]; then … return 0; filines 17–39NEW

Purpose: the entire single-file code path, self-contained inside one if block at the top of main(), guarded on input_bam being set.

Key logic: resolves the actual downloaded BAM's local path via dx describe "$input_bam" --name (getting the original filename) combined with the predictable dx-download-all-inputs path convention; applies the same sed transform used in array mode (duplicated here rather than shared, for the same reason discussed in the purple/amber walkthroughs — no shared runtime between the two code paths); on passthrough, cps the input rather than re-invoking samtools reheader on a no-op transform (cheaper, and avoids samtools re-writing a BAM that doesn't need it); always indexes and always registers both outputs before return 0, which is what makes it stop before reaching the original array-mode code below.

06 Function walkthrough: array mode (v1.0.0, unchanged)

Gather inputs into bam_files[], loop, reheader-or-skiplines 41–128ORIGINAL

Purpose: the pre-existing behaviour, reproduced here only to show it is genuinely untouched by the v1.1.0 change.

Key logic: collects every file from input_file and input_file_array into one bash array bam_files, then loops over it. Per file: derive output filenames by appending _$mode to the base name (so sample.bam → sample_add_chr.bam, avoiding any collision with the original filename); if already in the target format, skip with a log message and no output for that file; otherwise reheader, index, upload, and append to the output_files/output_indices arrays via dx-jobutil-add-output … --array (the --array flag appends to a growing array output rather than setting a single scalar/file value, which is how multiple files accumulate into one declared array output across loop iterations).

07 Line-by-line: the passthrough check (single-file mode)

src/eggd_chr_prefix.sh : 25–33 Detect already-correct format, and — unlike array mode — always emit outputs either way 
samtools view -H "$sf_bam" > inputs/sf_orig.sam                    # ①
sed "$sf_sed" inputs/sf_orig.sam > inputs/sf_new.sam
if cmp -s inputs/sf_orig.sam inputs/sf_new.sam; then                # ②
    echo "Single-file mode: already in '$mode' format - passthrough."
    cp "$sf_bam" "$sf_out"                                        # ③
else
    echo "Single-file mode: reheadering to '$mode'."
    samtools reheader inputs/sf_new.sam "$sf_bam" > "$sf_out"          # ④
fi
samtools index "$sf_out" "${sf_out}.bai"                              # ⑤
dx-jobutil-add-output output_bam "$(dx upload "$sf_out" --brief)" --class=file       # ⑥
dx-jobutil-add-output output_bai "$(dx upload "${sf_out}.bai" --brief)" --class=file
①
Header-only extraction. samtools view -H prints just the header (the @SQ/@RG/etc. lines), never touching the actual aligned reads — this is what makes the whole operation cheap regardless of the BAM's size; only text a few KB long is being compared and potentially rewritten.
②
cmp -s — silent byte comparison. -s suppresses cmp's normal output and just sets its exit status: 0 if the two files are byte-identical, non-zero otherwise. Used here purely for its exit code inside the if, not for any text it would print.
③
The line that exists only in single-file mode — this is the whole point of v1.1.0. Array mode's equivalent branch (line ~112 in the original code) does nothing here at all — no copy, no output. This cp is what guarantees output_bam always gets populated, satisfying the next workflow stage's input requirement even when no actual header change was needed.
④
samtools reheader — the actual header swap. Given a new header file and the original BAM, this writes a new BAM with the header replaced and the read data streamed through unchanged — it does not decompress and re-encode every alignment record, which is why this whole operation is fast even on a large BAM.
⑤
Unconditional indexing, regardless of which branch ran. Whether $sf_out came from cp or from samtools reheader, it's a BAM without a companion index yet — samtools index always runs after the if/else, not duplicated inside each branch.
⑥
Both outputs are always registered — this line is never skipped. There is no code path through this function that reaches the end without calling both dx-jobutil-add-output lines — reinforcing, at the point of upload, the same guarantee the passthrough copy exists to provide: this app never emits nothing.
